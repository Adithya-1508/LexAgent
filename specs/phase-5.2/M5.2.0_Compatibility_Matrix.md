## 2. Four-Tier Test Classification

To prevent regressions during Phase 5.2 while hardening the legal retrieval and verification engine, all existing tests are classified into four distinct categories:

### Category 1: Unchanged and Passing (113 Tests)
These tests exercise subsystems whose interfaces, invariants, and behaviors remain fully preserved in Phase 5.2:
- **`tests/test_models.py` (4 tests):** Tests basic Pydantic model serialization, validation, and `ConfigDict(extra="forbid")`. Backward-compatible default fields ensure existing fixtures continue to parse without error.
- **`tests/test_tools.py` (6 tests):** Gratuity calculations, basic salary vs total salary rules, part-time proration, and statutory citation mapping.
- **`tests/test_routing.py` (3 tests):** Fast intent classification, direct calculator dispatch, and out-of-scope jurisdiction rejection.
- **`tests/test_agent.py` (45 tests):** LangGraph execution loops, conversation state preservation, missing-information clarification prompts, and calculator delegation.
- **`tests/test_ingestion.py` (20 tests):** Structural loading of documents, provision lists, and SHA-256 manifest verification.
- **`tests/test_legal_safety.py` (18 tests - non-retrieval subsets):** Adversarial prompts targeting DIFC/ADGM boundaries, non-existent article numbers, and calculator parameter fuzzing.
- **`tests/test_evaluation.py` (17 tests):** Manifest integrity, derived source checking, and benchmark evaluation harness.

### Category 2: Requiring Test-Fixture Migration / Test Opt-In in M5.2.1–M5.2.3 (20 Tests)
These tests execute retrieval queries against the Phase 5.1 MVP provisions (`data/official_sources/fdl_33_2021_provisions.json` and `cabinet_resolution_1_2022_provisions.json`):
- **Modules Affected:** Subsets of `tests/test_retrieval.py` (approx. 10 tests), `tests/test_synthesis.py` (approx. 8 tests), and `tests/test_agent.py` (approx. 2 end-to-end RAG tests).
- **Root Cause:** In Phase 5.2, `LegalProvision.publication_state` defaults to `LEGACY_UNVERIFIED`, and production `RetrievalFilters.allow_legacy_unverified` defaults to `False`. Under strict production settings, ordinary retrieval fails closed and will not return legacy unverified provisions.
- **Transition Protocol:** 
  1. In Phase 5.1 test fixtures, tests that intentionally assert retrieval behavior on legacy unverified fixtures will pass `RetrievalFilters(allow_legacy_unverified=True)`.
  2. During M5.2.2 and M5.2.3, as official snapshot-verified provisions are ingested and assigned `publication_state = VERIFIED_PUBLISHABLE`, tests will transition back to the default `allow_legacy_unverified=False`.
  3. No legacy provision will be automatically promoted to `VERIFIED_PUBLISHABLE` without verified snapshots (`ADR-005`).

### Category 3: Intentionally Changed Behavior (12 Tests)
Subsystems where Phase 5.1 had architectural limitations or hardcoded implementations that are deliberately upgraded in Phase 5.2:
- **Collision Elimination in `RetrievalIndex`:** In Phase 5.1, `RetrievalIndex.__init__()` raised `ValueError` on duplicate `(alignment_id, language)`. In Phase 5.2, multiple versions per `logical_provision_id` are explicitly supported and disambiguated by `version_id` and effective date intervals (`[effective_from, effective_until]`).
- **Data-Driven `claim_key_registry.json`:** In Phase 5.1, `CitationVerifier` hardcoded 14 alignments in `_ALIGNMENT_CLAIM_KEYS`. In Phase 5.2, claim keys are loaded from an external, version-scoped, checksummed registry (`claim_key_registry.json`).
- **Caveat Disclosure Enforcement:** In Phase 5.1, no caveats existed. In Phase 5.2, provisions with `PUBLISHED_WITH_CAVEAT` (such as Article 51 under CR 96/2023) require explicit opt-in (`include_caveated=True`) and verification that caveat disclosures are rendered in final responses.

### Category 4: Existing Failures Unrelated to Phase 5.2 (0 Tests)
- **Status:** **Zero failures.** The baseline test suite is 100% green on `main`.

## 3. Backward-Compatibility Safeguards

1. **`ConfigDict(extra="forbid")` Preservation:** Every Pydantic model maintains strict extra-field forbidding. All new Phase 5.2 fields have default values (`None`, `False`, or safe enums), ensuring that existing JSON fixtures load without breaking schema validation.
2. **Deterministic Fallback for Missing Identifiers:**
   - If `logical_provision_id` is omitted in legacy JSON, the system binds it to `alignment_id`.
   - If `version_id` is omitted, the system binds it to `f"{alignment_id}@legacy"`.
3. **Continuous CI Verification:**
   - The `core-minimal` CI job continues to run on Python 3.11 with only `pydantic>=2.7,<3` installed.
   - All Phase 5.2 acquisition tools and parsers are quarantined into `[project.optional-dependencies].corpus`.
