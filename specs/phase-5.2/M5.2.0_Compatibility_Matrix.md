## 2. Four-Tier Classification Methodology

Every single test in the baseline repository has been inspected at the source code level to eliminate all approximations, double-counting, or unsupported claims:
- **Tier 1: Unchanged and Passing (118 Baseline Tests):** Tests whose execution, interfaces, and assertions remain fully valid without any fixture modification or code change.
- **Tier 2: Requiring Test-Fixture Opt-In in M5.2.1–M5.2.3 (22 Baseline Tests):** Tests that execute retrieval queries against on-disk `fdl_33_2021_provisions.json`. Because Phase 5.2 defaults `publication_state` to `LEGACY_UNVERIFIED` and production `RetrievalFilters.allow_legacy_unverified` to `False`, these tests will require `allow_legacy_unverified=True` on test fixtures or queries during M5.2.3 (PR-6) until verified snapshots are ingested.
- **Tier 3: Intentionally Changed Behavior (5 Baseline Tests):** Tests asserting specific legacy behaviors (e.g. strict duplicate alignment crashes or hardcoded alignment claim verification) that are deliberately upgraded by Phase 5.2 architecture.
- **Tier 4: Existing Failures Unrelated to Phase 5.2 (0 Baseline Tests):** Confirmed zero existing failures on `main`.
